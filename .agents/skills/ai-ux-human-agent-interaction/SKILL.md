# AI UX & Human-Agent Interaction Designer

## Mission
Design intuitive, accessible, professional interfaces for AI-powered applications and autonomous agent systems.
Ensure users understand system status, capabilities, limitations, and available controls.

## Activate When
Use this skill when:
- Designing or refining the `job_search_automation` web dashboard (`docs/index.html`).
- Improving email reports and summary notifications.
- Developing or styling job card layouts, badge indicators, or score visualizers.
- Improving search, filtering, and category navigation.
- Redesigning UI components in `src/ui_builder.py`.
- Improving mobile responsiveness and RTL (Right-to-Left) typography.
- Evaluating usability, cognitive load, and accessibility (a11y).

## Required Inputs
Identify:
- Target user: Ido Gal (Practical Engineer in Energy & Drones).
- Primary user journeys: Daily review of Top 5 matching jobs, filtering by domain (Energy vs. UAV), reading AI evaluation rationale, clicking to apply.
- Product objectives: Zero cognitive clutter, clear distinction between passing and rejected jobs, transparent scoring reasons.
- Existing UI: `docs/index.html` generated by `src/ui_builder.py`.
- Brand & visual guidelines: Clean modern dashboard, RTL Hebrew support, professional dark/light contrast.
- Technical stack: Vanilla HTML5, modern CSS3 (Flexbox/Grid, CSS variables), lightweight JS for client-side filtering.
- Supported devices: Desktop browsers and mobile smartphones.

## Execution Workflow

### Step 1 — UX Audit
Inspect the existing interface (`docs/index.html`).
Evaluate:
- **Information hierarchy:** Are the top matching jobs immediately prominent?
- **Navigation clarity:** Can the user effortlessly toggle between Energy and Drones?
- **Cognitive load:** Is the AI explanation concise and highlighted, or buried in walls of text?
- **Visual consistency:** Are score badges, tags, and date stamps styled uniformly?
- **Responsiveness:** Does the card grid adapt smoothly to narrow smartphone screens?
- **Accessibility & RTL:** Is the Hebrew text properly aligned right-to-left (`dir="rtl"`) with legible font sizes?
- **Empty & Error states:** What happens when 0 new jobs were found today?

### Step 2 — User Journey Mapping
Map the user flow:
1. Open daily digest (email or dashboard link).
2. Scan high-level metrics (Total jobs scanned, Top 5 matches today).
3. Inspect high-score job cards: Title, Company, Location, Match Score badge.
4. Expand AI analysis: Read *why* the job fits (Hands-on, SCADA, practical engineering alignment) and salary estimation.
5. Direct Action: Single-click button to open original job application link.

### Step 3 — Information Architecture
Organize dashboard sections:
- **Header & Timestamp:** Last updated time, run status indicator, scanned count.
- **Filter Bar:** Category filters (Energy, Drones, All), minimum score slider, search query.
- **Top Matches Grid:** Prominently styled job cards with clear visual hierarchy.
- **Detailed Job Drawer / Card:** Full AI reasoning, pros/cons breakdown, original posting link.
- **Archive / History:** Access to previous days' jobs.

### Step 4 — Design System & Tokens
Define clean, reusable UI tokens:
- **Colors:** Clear semantic palette (e.g. Emerald for Match >= 85, Amber for 70-84, Slate for Neutral).
- **Typography:** Modern Hebrew sans-serif typography (e.g. system fonts / Assistant / Heebo) with comfortable line-height.
- **Spacing:** Consistent 8pt grid for padding, margins, and card gaps.
- **Components:** Cards, score pills, tags, action buttons, filter chips.

### Step 5 — Human-Agent Interaction & Transparency
For autonomous reporting:
- **Task Status:** Clearly state when the scrape ran, how many jobs were filtered out deterministically, and how many were evaluated by Gemini.
- **Transparent Reasoning:** The AI must explicitly explain *why* a score was given (e.g., "Practical Engineer accepted (+15), SCADA experience match (+20)").
- **Clear Error States:** If Comeet or LinkedIn had an error, report it cleanly without breaking the dashboard UI.

### Step 6 — Interaction Safety & Polish
- Open external application links in a new tab with `target="_blank"` and `rel="noopener noreferrer"`.
- Prevent accidental dismissal or data loss.
- Ensure all interactive buttons have clear hover, active, and focus states.

### Step 7 — Usability Validation
Evaluate against real user scenarios:
- Does the dashboard render properly on mobile Safari and Chrome?
- Can a job be evaluated in under 5 seconds of scanning?
- Are tags easily readable in both bright daylight and dark mode?

### Step 8 — Iterative Improvement
Prioritize improvements based on:
1. User clarity and speed of job review.
2. Mobile readability.
3. Code simplicity in `src/ui_builder.py` (avoid heavy frontend frameworks; keep it pure, fast, dependency-free HTML/CSS).

## Quality Standards
- Interfaces must communicate system state clearly.
- Match score and rationale must be visible without excessive clicking.
- RTL layout must be strictly enforced for Hebrew text.
- Responsive design must function seamlessly on mobile devices.
- No heavy external JavaScript dependencies that slow down loading.

## Guardrails
- Do not add complex frontend frameworks (React, Vue) when pure HTML/CSS is faster and simpler.
- Do not hide the AI's reasoning from the user.
- Do not use misleading badges or unverified claims.
- Do not break existing dashboard generation scripts.

## Deliverables
1. UX audit of `docs/index.html`.
2. UI component specifications for `src/ui_builder.py`.
3. Design system tokens (colors, typography, spacing).
4. Usability validation report for desktop and mobile.

## Definition of Done
The dashboard is intuitive, fast, mobile-responsive, and allows the user to quickly review matching jobs and understand the AI's exact rationale.
